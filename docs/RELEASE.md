# Almavorn for Linux

## Установка из исходников

На Ubuntu, Debian, Arch Linux и Artix x86_64:

```sh
curl -fsSL https://raw.githubusercontent.com/Molten-Zharr/Almavorn/main/install.sh | bash
```

Команда установит недостающие зависимости, склонирует проект в
~/.local/src/almavorn, соберет обе версии и добавит плеер в меню приложений.
Для обновления закройте плеер и повторите команду. При необходимости системный
установщик запросит пароль через sudo. Папка с измененными исходниками не
перезаписывается; для отдельной копии можно передать --source-dir и полный путь.

Уже подготовленный репозиторий можно собрать и установить так:

```sh
python3 scripts/package-release.py --install
```

Локальная установка получает отдельное имя по коммиту и собранным программам.
Повтор той же установки сохраняет действующие файлы. Предыдущие версии остаются.

## Установка готового выпуска

В архиве две версии: графическая `bin/almavorn` и консольная `bin/almavorn-tui`.
Для запуска из распакованного архива установка не обязательна.

Для установки в меню приложений выполните из папки архива:

```sh
python3 install.py
```

Python 3 нужен только установщику. Он копирует выпуск в
~/.local/opt/almavorn/ВЕРСИЯ, добавляет команды в ~/.local/bin и пункт
Almavorn в меню приложений; права администратора не нужны.
Перед обновлением закройте плеер и запустите установщик из нового архива:
он переключит обе команды и пункт меню на новую версию, сохранив прежнюю
сборку и ее файлы запуска в launchers-before-ВЕРСИЯ внутри старой установки.
Посторонние или измененные файлы не заменяются; повторная установка той же
сборки сообщает, что она уже установлена. Если переключение не удалось, прежние файлы запуска
восстанавливаются, а незавершенная новая установка остается для разбора.
Если `~/.local/bin` отсутствует в PATH, используйте меню или полный путь.

Библиотека и настройки хранятся отдельно: обычно `~/.local/share/almavorn`.
Установка не переносит и не удаляет музыку. Для отдельной библиотеки:

```sh
./bin/almavorn --data-dir /путь/к/библиотеке
./bin/almavorn --version
```

Не открывайте одну библиотеку одновременно в нескольких экземплярах.
Перед первым запуском с существующей библиотекой сохраните копию ее каталога
при закрытом плеере. Старая база almavorn.duckdb переносится через DuckDB CLI;
если ее нет, переносится almavorn.sqlite3; исходные файлы сохраняются.

## Совместимость

Выпуск предназначен для Linux x86_64 с glibc. Нужны ALSA, libstdc++ и
драйвер OpenGL с Wayland или X11 для графической версии. SQLite, SoundTouch
и шрифты уже включены. Минимальная версия системных библиотек зависит от
среды сборки; компилятор, glibc и исходный коммит записаны в BUILD_INFO.json.
Локальная сборка на Artix предназначена прежде всего для этого компьютера.
Архив GitHub собирается отдельно на Ubuntu 22.04. Windows, macOS и Linux
с musl в этом выпуске не поддерживаются.

Проверка скачанного архива до распаковки:

```sh
sha256sum -c SHA256SUMS
tar -xzf almavorn-0.1.3-linux-x86_64.tar.gz
```

## Лицензии и повторная сборка

Приложение написано на Rust. Изменение темпа и высоты звука использует
SoundTouch — библиотеку на C++. Ее исходники собираются вместе с приложением,
поэтому для сборки нужны C++ и libclang. Готовому плееру компилятор не требуется.

Код Almavorn распространяется по MIT. Зависимости и шрифты сохраняют свои
лицензии: перечень приведен в THIRD_PARTY_NOTICES.md, тексты в share/licenses.
SoundTouch статически включен по LGPL-2.1, Symphonia использует MPL-2.0.
В share/source находятся точные исходники приложения с Cargo.lock и архив
всех разрешенных для Linux зависимостей, включая SoundTouch и его Rust-обертки.
Изменений в исходники зависимостей при упаковке не вносится.

Для сборки нужны Rust с поддержкой edition 2024, C++ компилятор, libclang,
заголовки ALSA и доступ к crates.io. Для Debian/Ubuntu список пакетов есть
в .github/workflows/release.yml. Распакуйте исходники приложения и выполните:

```sh
cargo build --locked --release --bins --all-features
```

Для изменения и повторного связывания SoundTouch распакуйте
share/source/dependencies.tar.gz рядом с исходниками приложения. В Cargo.toml
приложения добавьте пути к распакованным библиотекам:

```toml
[patch.crates-io]
soundtouch = { path = "../soundtouch-0.5.4" }
soundtouch-ffi = { path = "../soundtouch-ffi-0.4.1" }
```

Измените нужные файлы, в том числе C++ в soundtouch-ffi/soundtouch-2_3_2,
и выполните `cargo build --release --bins --all-features` без --locked,
поскольку локальные пути изменят Cargo.lock. Полученные программы находятся
в target/release; их можно запускать напрямую без установки и подписей.

## Подготовка следующего выпуска

Релиз собирается из конкретного коммита, помеченного тегом: последующие
изменения в main попадут уже в следующий выпуск.

Обновите версию приложения в Cargo.toml и записи almavorn в Cargo.lock,
добавьте описание в releases/vВЕРСИЯ.md и зафиксируйте эти файлы вместе
с готовыми изменениями. Отправьте коммит в main и соберите локальный архив:

```sh
python3 scripts/package-release.py
```

Архив и SHA256SUMS появятся в target/dist/ВЕРСИЯ; существующий каталог выпуска
не перезаписывается. Для локальной установки распакуйте архив и выполните
python3 install.py внутри его папки.

Поставьте тег на подготовленный коммит и отправьте его; пример для следующей
версии 0.1.4:

```sh
git tag -a v0.1.4 -m "Almavorn 0.1.4"
git push origin refs/tags/v0.1.4
```

GitHub Actions соберет архив на Ubuntu 22.04, создаст черновик GitHub Release
и загрузит в него архив и SHA256SUMS. После успешной загрузки выпуск
автоматически публикуется для скачивания. Если загрузка не завершилась,
выпуск остается черновиком. Дождитесь успешного завершения Release в Actions
и проверьте описание и файлы на странице
[Releases](https://github.com/Molten-Zharr/Almavorn/releases).
Раздел Packages для этих архивов не используется.

## GitHub Packages

Packages хранит библиотеки и контейнеры для пакетных менеджеров, например
npm, NuGet и Docker. Almavorn распространяется через Releases: там находятся
готовые программы для скачивания. Создавать Packages для установки плеера
не требуется. [Описание GitHub Packages](https://docs.github.com/en/packages/learn-github-packages/introduction-to-github-packages).

Описания существующих выпусков обновляются из releases/*.md при отправке
этих файлов в main. Архивы и состояние публикации при этом не меняются.
